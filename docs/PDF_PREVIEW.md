# PDF 候选扫描与本地预览（v0.9.0 开发版）

当前正式预览下载仍为 v0.8.0。本文描述 v0.9.0 的新增实现，须经合并与发布后进入下载包；DOCX/XLSX 尚未加入签名扫描或预览。

“文件扫描”和“电脑恢复”的签名模式支持连续 PDF 候选，保留来源身份、绝对偏移、长度、范围 SHA-256 与结构检查依据。在结果页筛选“文档”，选中 PDF 后点击“预览选中图片 / 视频 / PDF”。窗口可翻页、缩放和停止渲染；关闭、改选、切换页面或工作目录会关闭预览并释放其持有的文档字节与图像。

原始磁盘仍须先通过工作目录与导出目标位于其他物理盘的只读预检，预检通过前不创建预览任务。普通文件与镜像、授权 Android 采集副本、iPhone 备份 blob，以及支持的文件系统元数据候选均沿用原有来源与摘要核验。普通采集仍是现存文件复制，不是删除证据。

| 项目 | 当前支持与限制 |
|---|---|
| PDF 布局 | PDF 1.0–1.7 / 2.0 的传统交叉引用表、单一修订、静态页树；实际内容还须符合下方资源和结构要求 |
| 范围检查 | `startxref` 指向交叉引用表；表项须绑定正确对象/代次；对象不重叠且覆盖非注释/空白区域，流按直接或间接 Length 核对 |
| 页面与引用 | 校验目录、页树父子关系、页数、对象引用及页面范围；不推测文件系统碎片或原文件可选尾随字节 |
| 流 | 支持未过滤、FlateDecode；图像 DCTDecode 同时检查 JPEG 结构与解码尺寸；其他过滤器保留为受限项 |
| 输入和解析上限 | 单项 16 MiB、200 页、10,000 个对象、200,000 次语法操作、32 层嵌套、64 KiB 字符串、32 MiB 总流解压检查 |
| 单页预览 | 50–200% 缩放，输出最多 400 万像素；每页独立进程，约 8 秒墙钟超时，可取消；监测到驻留内存超过 512 MiB 时结束该进程 |
| 不支持或拒绝 | 交叉引用流、对象流、混合布局、增量修订、加密、脚本、表单、附件及外部引用；不执行、不解密、不访问引用地址 |

PDF 没有适用于任意镜像的通用原文件长度。候选止于通过检查的 `%%EOF` 行，包含其行结束符（如有），不吸收任意尾随数据。流内的伪 EOF 不作为文件边界；检测到后续对象/交叉引用或 Prev 时，增量修订明确受限，不将较早修订当作最终文档。边界无法确认时不提供预览/校验导出。

检查通过仍显示 `candidate`，删除状态未知。“PDF 结构与对象范围检查通过”不是全部页面、字体或内容正确的保证，也不是逐字节取证重建；页面可显示也不证明文件曾被删除。扫描不提取文件，导出使用原始候选范围，源/目标摘要一致才记录独立导出结果。

预览将已核验的字节通过匿名管道交给 QtPdf 工作进程，仅返回静态 PNG 页面，不传入来源路径或 URL，不创建文档预览副本，不提供脚本、表单、附件、链接或浏览器交互。页码/缩放不改变源或候选状态。停止、超时和异常会清除旧页面并结束该工作进程；新页失败时不保留上页画面造成误认。

资源限制用于约束输入、解析和输出；驻留内存按操作系统可用信息采样，采样间隔可能短暂超过阈值，不是统一的内核硬内存配额。PDFium 会预留较大的虚拟地址空间，该预留不等于实际驻留内存。真实复杂文档、不同系统字体及桌面体验仍需后续验收；按本轮要求跳过 M5 实机，状态保留为未执行。
