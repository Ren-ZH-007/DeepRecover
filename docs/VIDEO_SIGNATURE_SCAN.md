# MP4/MOV 连续签名扫描（v0.8.0 预览版）

[v0.8.0 预览版已发布](https://github.com/Ren-ZH-007/DeepRecover/releases/tag/v0.8.0)，提供 Windows x64 和 macOS 双架构包。正式附件与三平台构建核验见[发布记录](releases/0.8.0/PUBLISHED.json)。

在“文件扫描”选择稳定的本地文件或镜像，或在“电脑恢复”中选择来源、分区与“JPG / PNG / MP4 / MOV 签名候选”。扫描只读访问源内容，不提取文件、不写入来源、不访问媒体引用地址。原始磁盘仍须先通过工作目录与导出目标位于其他物理盘的预检。

候选结果可筛选“视频”，查看来源、源内绝对偏移、长度、内容检查、范围 SHA-256 和删除依据。通过检查的候选可使用既有的[视频预览](VIDEO_PREVIEW.md)与校验导出；历史可在源缺失时回读，但重新预览或导出需要来源仍可访问、身份及摘要符合记录。

| 检查项目 | 支持范围 |
|---|---|
| 文件头与布局 | `ftyp` 开始的自包含、非分段 MP4/MOV；`moov` 可位于媒体数据前或后 |
| 编码与轨道 | 单 H.264 `avc1` 视频轨，可带 AAC `mp4a` version 0 音轨；最多 8 个轨道。只有一条 AAC 音轨、没有视频轨的作为 M4A 音频报告，见[音频说明](AUDIO_SIGNATURE_SCAN.md) |
| 媒体范围 | `stco/co64`、`stsc`、`stsz` 联合确定块范围，要求全部位于声明的 `mdat` 载荷内且不重叠；支持多个 `mdat` |
| 一致性 | 基础配置、时钟、采样数量与时长、同步采样和受支持的采样分组检查；不解码 H.264/AAC 比特流 |
| 资源限制 | 单候选 64 MiB、单 `moov` 元数据 8 MiB、20 万采样/表项、1 万盒、200 万次范围检查；扫描最多 1 万候选 |
| 保留的证据 | 来源身份、绝对偏移、范围长度、通过检查时的范围摘要，以及检查版本、轨道/采样/块/媒体盒数量和边界依据 |

MP4/MOV 没有通用的文件结束标记。本版接受的连续候选止于**最后一个必需盒的末尾**：已读到电影元数据，且所有采样引用均由已声明的媒体盒覆盖。不把任意镜像结尾或尾随数据猜作原文件边界。候选可能不包含原文件的可选尾随盒或其他附属数据，不等同于完整原文件的取证重建。

以下结果分别保留原因，不能作为已验证媒体预览或导出：

- 截断：未获得完整容器或尚未覆盖全部采样。
- 结构失败：盒或表项不一致、媒体范围落入头部/元数据、跨越媒体盒或相互重叠。
- 边界未知：例如长度为零、语义为延伸至文件结尾的 `mdat`，无法在镜像中确定原文件结尾。
- 资源受限、不支持的布局/编码、分段容器、加密或外部引用：显示对应原因；不解密、不拼接、不访问引用地址。

成功候选显示“视频容器与采样范围检查通过”，仍是 `candidate`，删除状态始终未知。结构检查不证明每一帧可解码、所有内容完整或文件曾被删除。预览还受 64 MiB、10 分钟、横竖屏 1080p、60 fps 及本机解码能力限制；扫描通过不保证预览成功。

连续签名扫描不能重组文件系统碎片。APFS/HFS+ 仅提供签名候选，不解析删除元数据，也不能绕过加密、TRIM 或覆盖。普通文件采集和摘要一致的复制均不描述为已删除数据恢复。
