# 音频签名扫描（未发布）

“文件扫描”和“电脑恢复”的签名模式新增音频候选：WAV、MP3 和 M4A。与图片、视频、PDF 和 Office 文档一样，候选会记录来源身份、绝对偏移、长度、范围 SHA-256 和结构检查依据，检查通过的可以导出。不提供音频预览，也不会解码或播放；选中音频点预览时会提示导出后用其他播放器打开。

## 支持范围

| 格式 | 识别 | 边界 | 结构检查 |
|---|---|---|---|
| WAV | `RIFF` 头且类型为 `WAVE` | RIFF 头记录的总长度；最后一个奇数长度块的补齐字节也计入 | `fmt ` 和 `data` 块各一个、顺序正确、不越界；PCM（8/16/24/32 位）、浮点（32/64 位）、A-law、μ-law，PCM 和浮点也可以是扩展格式（WAVE_FORMAT_EXTENSIBLE）；声道数、采样率、块对齐、字节率自洽；音频数据是整数个采样帧 |
| MP3 | 以 ID3v2 标签开头（v2.2–2.4），标签后紧跟（或在少量零填充后）一个 MPEG Layer III 帧 | 首帧的 Xing / Info 或 VBRI 头记录的音频字节数；末尾的 ID3v1 标签也计入 | 逐帧核对帧头，版本、采样率和声道数保持一致；逐帧走完的总长度必须和记录的字节数完全相等 |
| M4A | 与 MP4 相同的容器（品牌 `M4A `、`M4B `、`F4A `、`F4B `，或只有一条音轨的其他 MP4 品牌） | 最后一个必需盒的末尾 | 与 MP4 视频相同的容器、采样表和媒体范围检查，要求只有一条 AAC 音轨 |

## 不能导出的情况

| 状态 | 原因 |
|---|---|
| 音频边界未确认 | MP3 没有记录总字节数的 Xing / Info / VBRI 头，或 WAV 的 RIFF 长度是 0 或 0xFFFFFFFF（流式写入未回填）。MP3 本身没有文件长度字段，无法确认文件在哪里结束 |
| 音频内容截断 | 到达来源结尾时数据块或帧还不完整 |
| 音频结构检查失败 | 格式字段不自洽、块越界或顺序错误、帧序列中断、M4A 采样范围不一致 |
| 暂不支持此音频布局 | ADPCM 等压缩 WAV、首个帧不是 Layer III 的 MP3、多条音轨或非 AAC 的 M4A |
| 达到音频检查限制 | 单项超过 64 MiB，或超过 50 万帧、1 万个块 |
| 加密音频 / 分段音频 / 音频含外部引用 | 与 MP4 视频相同的容器限制 |

## 不算作候选的内容

- 不是 WAVE 的 RIFF 文件（AVI、WebP、RMID 等）不入库、不计数。AVI 里的 MJPEG 帧本身是有效的 JPEG，仍会作为图片候选找到。
- 不带 ID3v2 标签的 MP3 不会被找到：裸的 MPEG 帧同步码只有 11 位，在任意数据里极为常见，按它搜索会产生大量误报。
- ID3 标签版本或长度字段不合法的不算候选。

## 尚不支持

- **FLAC**：FLAC 没有文件总长度字段，最后一帧的结束位置必须解码子帧才能确定；只靠帧校验码猜测，有相当高的概率猜错位置。在实现子帧解析之前不做 FLAC 签名候选。
- OGG、AAC 裸流（ADTS）、WMA、AIFF、RF64（超过 4 GiB 的 WAV）。

## 碎片文件

和其他签名格式一样，**音频签名扫描只能恢复在磁盘上连续存放的文件**，不会拼接碎片，见 [Office 文档签名扫描](OFFICE_SIGNATURE_SCAN.md#碎片文件)中的说明。

## 测试

自动化测试使用 `tests/fixtures/audio/` 里由 ffmpeg 生成的真实文件（说明见该目录的 README），以及测试中构造的 WAV：验证精确边界、各种 WAV 格式和块布局、不是 WAVE 的 RIFF 不算候选、格式不自洽和截断、MP3 帧损坏、字节数不符、标签后零填充、无 Xing 头时边界未确认、M4A 两种盒顺序和通用品牌、视频识别不变、两种扫描器结果一致、导出字节一致，以及含音频时断点续扫结果和一次扫完相同。开发时另用 ffmpeg 完整解码了导出的每个文件，均无错误。
