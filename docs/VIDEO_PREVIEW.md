# 本地视频预览

已合并的 v0.8.0 可从[MP4/MOV 连续签名扫描](VIDEO_SIGNATURE_SCAN.md)的通过候选进入本预览流程，播放限制保持不变；尚未正式发布，见[发布状态](releases/0.8.0/STATUS.json)。下方 v0.7.0 范围保留为发布记录。

[v0.7.0 预览版已发布](https://github.com/Ren-ZH-007/DeepRecover/releases/tag/v0.7.0)，提供 Windows 和 macOS 双架构包。本轮增加播放预览，不增加视频签名扫描、视频碎片重组或文件修复能力。

## 操作

1. 从已完成的 Android 普通文件采集、未加密 iPhone 备份索引，或受支持的电脑删除记录结果中选择一项 MP4/MOV。
2. 点击结果页右侧“预览选中图片 / 视频”。程序先后台核对来源绑定、文件身份、大小和已有摘要，再检查预览支持条件。
3. 独立窗口显示首帧后自动暂停。点击播放/暂停，或拖动进度；整个预览始终静音，不连接音频输出。
4. 关闭窗口、改选候选、分页、筛选、切换页面、开始其他任务或切换工作目录时停止旧预览。重新打开结果只读历史，需再次明确预览才访问来源。

## 支持与限制

| 项目 | 首版范围 |
|---|---|
| 容器 | 自包含、非分段的 MP4/MOV，单视频轨道 |
| 视频编码 | H.264 的 `avc1` 记录；不支持 HEVC、`avc3`、加密或引用电影 |
| 音频 | 无音轨或 AAC 音轨；始终静音，不提供音量/音轨选择 |
| 输入 | 单项最多 64 MiB，声明时长最多 10 分钟；横屏 1920×1080 或竖屏 1080×1920 以内，含旋转后的输出检查；采样参数不超过 60 fps |
| 资源 | 来源内容核验后读入内存，使用可定位的内存设备播放，不创建预览副本、缓存或临时媒体文件 |
| 外部来源 | 拒绝播放列表、外部媒体引用和未支持的容器结构，不将原始路径或网络 URL 传给播放器 |

超出范围时可按原有导出流程保存到安全目标，再使用本机播放器检查。部分常见手机视频使用 HEVC/4K、分段结构或其他轨道布局，本版会明确拒绝；不能根据 `.mp4/.mov` 扩展名保证可播放。加载超时、解码失败或本机解码器不可用时清除旧画面并停止预览，不显示解码器的原始路径/异常文字。

容器检查只是播放准入条件，不是完整 MP4/H.264 结构与比特流校验。能显示首帧、播放或拖动都不证明视频每一帧完整，也不证明数据曾被删除。视频后端的内部解码资源由 Qt/平台管理，输入与元数据限制不等于其所有内部内存分配的硬上限。

## 来源与状态

- Android 只读工作目录里的采集副本，不重新访问手机；先核对采集摘要。
- iPhone 只读绑定备份根目录内的 blob，核对索引时保存的身份和大小；加密备份仍不解密。
- 电脑候选沿用原有完整布局、分配状态与摘要门禁；碎片按记录的逻辑顺序读取。原始盘仍先检查工作目录位于另一块物理磁盘，无法确认时不建立预览任务。
- JPG/PNG 图片预览保持原有行为与 32 MiB/1,600 万像素限制；视频和图片都不改写候选完整性、删除依据或导出状态。

播放器只接收核验时生成的内存快照，不会随后自动读取已变化的来源。关闭时停止媒体读取、释放压缩缓冲和已解码帧。后台预览准备使用协作取消；Qt 原生解码与停止操作仍需等待后端处理，不能宣称可强制中断任意原生调用。

## 验证

自动化包含来源变更/摘要错误、备份与采集目录边界、碎片顺序、大小/时长/尺寸/采样限制、外部及隐藏引用、取消和无效解码。真实 Qt 流程使用自生成的两秒 H.264/AAC 测试片段，验证有效帧、静音、暂停、拖动、旧画面清理及关闭期间释放。

编译包的门禁会实际运行 Qt 多媒体后端；缺少插件、无法解码测试帧或不能释放缓冲均不能通过。该合成验证不代替真实长视频、不同手机编码和桌面体验验收。
